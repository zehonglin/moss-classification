# 苔藓识别系统 UI 重设计

> 日期：2026-08-08
> 范围：推倒重写 UI 层（`app/ui/`），保留控制器/服务/驱动层
> 视觉参考：`.superpowers/brainstorm/1305-1786115433/content/`（layout-operator / engineer-layout-v2 / banner-states-v2 / correction-dialog / final-mockup-v2 / select-history-v2）

## 1. 目标与范围

**目标**：把现有"工程师视角、信息密集"的单界面，重设计为面向**产线操作员**的现代浅色界面，并提供**工程师模式**承载全部调试参数。核心是让品级结果一眼可辨、操作抗误触、参数按需展开。

**在范围内**：
- 重写 `app/ui/main_window.py`、`app/ui/widgets.py`、`app/ui/style.qss`
- 拆分独立组件文件（见 §12）
- 双模式、品级横幅、顶部统计栏、历史分页、气泡纠错、toast 通知等全部 UI 行为
- 为支持新 UI，**新增**少量 controller / DB 方法（见 §9.2），不修改现有方法签名

**不在范围内**（§13）：
- 推理/相机/存储/归档逻辑
- controller 现有信号与方法签名
- 训练 / 评估 / 导出 ONNX 流程
- PLC / 传送带联动（仍仅预留接口）

## 2. 设计原则

1. **品级为王**：操作员界面一切为"一眼看品级"服务；品级是最大、最醒目、唯一会变色的主信息。
2. **状态正交**：**背景色 = 品级**（A/B/C/D），**图标/角标 = 异常状态**（⚠ 复检 / 拒采 / 已纠错）。两套语义绝不混用，避免低置信的橙色与品级 C 的橙色打架。
3. **双模式分层**：操作员模式极简、抗误触；工程师模式参数同屏、可即时调试。两模式共享顶部统计栏，切换时顶部位置不变。
4. **警告不抢主信息**：品级横幅只承载品级结果；所有警告（磁盘/无图/连续拒采/超时）走右上 toast，自动消失、可手动关。
5. **产线节奏**：3 s/托盘，远距离/余光可辨优先于信息密度。

## 3. 技术栈与运行环境

- **框架**：PySide6 / Qt Widgets + QSS（沿用，不引入 Web）
- **自适应**：布局级自适应（QBoxLayout + QSplitter + stretch），Qt6 默认高 DPI 缩放
- **目标分辨率**：1920×1080 主设计；1280×800 为最小可用（不裁切、关键区可见）
- **输入**：键鼠（非触摸）；单屏
- **自适应不做**：断点式布局切换（产线固定屏，投入产出比低）

## 5. 信息架构（双模式）

两模式共享**顶部统计栏**；其下布局不同。

### 5.1 操作员模式（默认）

```
┌─ 顶部统计栏（§5.3，与工程师一致）──────────────────────┐
├─ 品级横幅（品级色整条，随结果变色）──────────────────┤
├─ 取景器（深色画框）──────┬─ 历史列表（分页，到底）──┤
│                          │  筛选: 品级▾ 状态▾ 查询   │
│                          │      [↓ 导出记录]         │
│                          │  历史项 × 当前页 50       │
│                          │  …占满到底…               │
├─ 底栏：连接相机 │ 开始运行 │ 停止运行 │ 拍照 ─────────┤
```

无参数栏。按钮在底栏横排。历史区垂直占满到底部按钮栏。

### 5.2 工程师模式

```
┌─ 顶部统计栏（§5.3，与操作员一致）──────────────────────┐
├─ 参数栏(左)──────┬─ 主区─────────────────────────────┤
│ 相机             │  品级横幅                          │
│  触发模式 ▾      ├─ 取景器──────┬─ 历史列表(分页)───┤
│  触发防抖        │              │  筛选 + 导出记录   │
│  分辨率          │              │  历史项 × 50       │
│  [软件间隔]*     │              │  …占满到底…        │
│  曝光(固定)      │              │                    │
│ 模型             │              │                    │
│  当前模型 ▾      │              │                    │
│  置信度阈值      │              │                    │
│ 质量检查 ▾       │              │                    │
│ ── 操作 ──       │              │                    │
│  连接相机        │              │                    │
│  开始运行        │              │                    │
│  停止运行        │              │                    │
│  拍照(软件触发)  │              │                    │
```

*软件间隔仅触发模式 = `software_continuous` 时显示，其余隐藏。画面/历史占满到底（无底状态栏，统计已上移）。操作按钮在参数栏底部纵向排列。

### 5.3 顶部统计栏（双模式一致）

从左到右：`logo(苔藓识别) │ 模式切换(操作员/工程师 ▾) │ 运行状态 │ 累计统计 │ 磁盘 │ 通知铃`

- **运行状态**：`运行中（实时图像）` / `运行中（历史图像）` / `已停止`，绿色呼吸点
- **累计统计**：`●A n  ●B n  ●C n  ●D n │ ✎纠错 n │ ⚠不合格 n`
- **磁盘**：`💾 nnnGB 可用`
- 选中历史时仍显示"运行中（历史图像）"——系统仍在采集，仅画面在看历史

**计数规则**：A/B/C/D 按**最终品级**统计（`corrected_label` 优先于 `prediction`）；原始 A 纠正为 B → **B +1、纠错 +1**（A 不计）；不合格（`quality_status != 'ok'`）单独计、不计入任何品级。

### 6.1 历史项（HistoryItem）

`缩略图(24–26px) │ 品级色字 + 置信度 │ [角标] │ 时间`，单行。

- 正常：品级色字 + 置信度（灰）
- 低置信（< 阈值）：前缀 ⚠ + 橙色 + `需复检` 角标
- 已纠错：品级字 + `已改X` 绿角标
- 拒采：红色 `⚠ 质量不合格 · {原因}`
- 选中：浅橙底 + 左侧 3px 品级色条 + 边框
- **不加** hover 快捷纠错入口（已确认）

## 7. 状态规范

### 7.1 品级横幅状态矩阵

| 状态 | 背景 | 内容 | 纠错入口 |
|------|------|------|----------|
| 正常品级 A/B/C/D | 品级色 | `当前品级` + 大字母 + 置信度进度条 + 数值 | ✎ |
| 低置信需复检 (< 阈值) | **品级色不变** + ⚠ + 白色脉冲边框 | `需复检` + 字母 + `置信度偏低` 徽章 + 数值 | ✎ |
| 拒采（质量不合格） | `#334155` 深灰 + 红 ⚠ | `质量不合格 · {模糊/过曝/欠曝}` + `未出品级` + `原图已留存` | 无 |
| 已纠错 | 品级色（最新纠正值） + `人工纠正` 徽章 | 字母（纠正后） + `原识别 X · n%` | ✎（可再次纠错） |
| 等待托盘（运行中无结果） | `#e2e8f0` 中性 | `运行中` + `等待托盘到位 · 光电触发抓拍` + spinner | 无 |
| 调试捕获（未入库） | 中性 | `调试捕获 · {品级} {置信度}` | 无 |

**关键不变量**：低置信与已纠错**绝不改品级背景色**；拒采因无品级用深灰底独立呈现。

### 7.2 运行状态标记（顶部）

`STATUS_IDLE` → `已停止`（灰点）；`STATUS_PREVIEWING`/`STATUS_RUNNING` 实时 → `运行中（实时图像）`（绿点呼吸）；选中历史 → `运行中（历史图像）`（绿点呼吸）。注：`历史图像` 是 **UI 本地派生态**（选中历史项时显示），controller 状态机仍为 RUNNING/PREVIEWING，**不新增 controller 状态**。

### 7.3 历史列表选中态

选中项：画面暂停实时流（不丢，返回即恢复）、显示该条原图；横幅切换为该条品级 + `正在查看历史记录` 徽章；画面顶部覆盖 `◀ 返回实时 │ 查看历史 · {时间} · 原图 2048×2048 │ 双击全屏 · 滚轮缩放`；**列表暂停自动刷新**，顶部显示 `⏸ 列表已暂停刷新 · N 条新记录 · 返回实时后更新`；统计栏继续累计。取消选中：再点该条 / 点返回实时 / ESC。

## 8. 交互规范

### 8.1 双模式切换

顶部 `操作员 / 工程师 ▾`。默认直接切；配置项 `ui.engineer_mode_password`（可选）：设置后切工程师模式弹 PIN 输入，验证通过才进入（产线防误调参数）。切换时顶部统计栏位置不变。

### 8.2 纠错闭环（气泡 A/B/C/D）

点横幅 `✎` → 锚定按钮弹出气泡（不遮画面）→ 四个**纯字母**品级色按钮 A/B/C/D（当前品级标 `当前`，白边框）→ 点目标品级即提交，气泡关闭。**替代现有文字输入框**，杜绝拼错。已纠错记录可再次点 `✎ 改正`，最新纠正覆盖前次，品级色随之变。

纠错仍触发现有 `controller.correct_prediction(id, label)`：更新 DB + 归档样本到 `data/corrections/<label>/`。不改后端。

### 8.3 选中历史 / 看原图

见 §7.3。双击画面 → 全屏放大原图（ESC 退出）+ 滚轮缩放。

### 8.4 分页

历史列表**每页渲染 50 条**（运行时 = 最近 50 条自动滚动；查询 = 当前页 50）。查询返回匹配总数 + 当前页数据，底部 `上一页 / 下一页 / 第 n 页 · 共 m 页`。导出可导出全部匹配（不受分页影响）。**解决现有 200/500 条同步渲染卡顿问题**（见 §10）。

### 8.5 导出记录

按钮命名 `导出记录`。点击弹小对话框：
- 格式：CSV（默认勾选，UTF-8 BOM，现有 8 列）
- `☐ 同时导出原图`：按品级/状态建子文件夹复制 PNG（便于挑样本重训），文件名沿用 `record_id_原预测.png`
- 导出范围 = 当前筛选条件下的全部匹配

### 8.6 警告 toast

右上角通知栈。来源 = controller `disk_space_warning` / `error_occurred` 信号。分类色：磁盘/性能警告（橙）、连续拒采/相机无图（橙）、致命错误（红）。自动消失（可配，默认 6s）+ 手动 ×。不抢占品级横幅。

## 9. 数据与接口

### 9.1 沿用现有 controller 信号/方法（不改签名）

信号：`image_updated(QImage)`、`result_updated(dict)`、`status_updated(str)`、`error_occurred(str)`、`disk_space_warning(str)`、`model_loaded(bool,str)`、`camera_info(str)`、`stats_updated(dict)`。

方法：`connect_camera/disconnect_camera`、`start_system/stop_system`、`capture_single`、`set_trigger_mode`、`set_camera_exposure`、`set_camera_resolution`、`reload_model`、`correct_prediction`、`get_recent_records`、`get_filtered_records`、`export_history_csv`、`get_available_models`、`shutdown`。

### 9.2 新增（为支持新 UI）

1. **累计统计聚合** — `DatabaseService.count_by_final_grade() -> dict`
   返回 `{A, B, C, D, corrected, rejected}`。`corrected = COUNT(corrected_label NOT NULL)`；`rejected = COUNT(quality_status != 'ok')`；品级按 `COALESCE(corrected_label, prediction)` 统计。controller 新增 `get_grade_summary()` 透传 + **新信号 `grade_summary_updated(dict)`**（与现有吞吐 `stats_updated` 职责分离，各按 2s 定时推）；TopStatBar 订阅 `grade_summary_updated`。
2. **分页查询** — `DatabaseService.search_records_paged(prediction, quality_status, page, page_size=50) -> (rows, total)`
   `get_filtered_records` 保留兼容；新 UI 走分页版。
3. **导出原图** — `SystemController.export_with_images(csv_path, image_root, rows, group_by='grade'|'status')`
   复制原图到 `image_root/<组>/<record_id>_<原预测>.png` + 写 CSV。

> 以上均为**新增**，不动现有签名。记录的 schema 不变（`corrected_label` / `quality_status` 列已存在）。

## 10. 容量与性能

| 项 | 值 | 说明 |
|----|----|----|
| 列表每页渲染 | **50** | 运行时最近 50 自动滚动；查询当前页 50，翻页 |
| 查询匹配 | 不限 | 分页看完所有匹配 |
| 导出 | 全部匹配 | CSV 轻量；原图按需 |
| DB 保留 | 60 天 | 现有归档策略，受磁盘水位兜底 |

**性能要点**（解决现有卡顿）：
- **分页**：列表恒定 50 条 widget，杜绝一次性渲染几百条 + 同步加载几百张缩略图导致的主线程冻结（现状 200 条已卡 0.5–1s）。
- **异步缩略图**：`HistoryItem` 先显示占位，`QThreadPool` 后台加载缩略图（沿用 `QImageReader.setScaledSize` 优化），完成后信号回主线程填 QPixmap。选中历史查看大图同理异步。
- **列表内存**：翻页/裁剪时显式 `deleteLater()` 旧 widget（沿用现有清理逻辑）。

## 11. 自适应与可访问性

- 布局级自适应：QSplitter（取景器/历史、参数栏/主区可拖动调宽）+ stretch 因子；1280×800 不裁切。
- Qt6 高 DPI 默认开，4K 不糊。
- 键盘：ESC 取消选中/关闭气泡/退出全屏；快捷键预留（模式切换、纠错）。
- 高对比：品级色对白字达 WCAG AA。
