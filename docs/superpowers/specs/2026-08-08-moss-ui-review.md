# 苔藓识别系统 UI 设计评审（对 2026-08-08 重设计规范的不同意见）

> 评审对象：`2026-08-08-moss-ui-redesign-design.md` + 当前 `app/ui/` 实现
> 配套可视化稿：`2026-08-08-moss-ui-v3-mockup.html`（操作员 + 工程师双模式高保真、状态矩阵、纠错气泡）
> 立场：肯定原规范的信息架构与状态正交原则，以下仅就**视觉系统、对比度、交互细节**提出修正。
> 修订（2026-08-08 二轮）：品级描述词按业务口径定为 **A 良好 / B 中等 / C 较差 / D 不合格**（均为正常品级，非动作指令）；复检仅由低置信度触发；质量不合格图像正常入库，去"拒采"措辞；计量单位"盘"；画面正方形铺满。

## 0. 总体评价

原规范做得对、应当保留的部分：

1. **双模式分层**（操作员极简 / 工程师全参数）是正确的信息架构，符合产线角色分离。
2. **状态正交**（背景=品级、图标=异常）是工业 UI 的最佳实践，必须坚守——但实现层有两处自己违反了这个原则（见 D4、D9）。
3. **警告走 toast 不抢横幅**、**质量异常深灰底独立呈现**、**分页 + 异步缩略图**的性能方案，均合理。
4. `banner_state` / `severity_for` 等纯函数抽离，可测性好，工程质量高。

以下按"关键分歧 → 实现缺陷 → 落地建议"展开。

## 1. 关键分歧（与原规范决策记录冲突，建议修订）

### D1 品级色对比度不达标，全 ramp 应下沉至 700 深度【P0】

规范 §11 声称"品级色对白字达 WCAG AA"，实测（相对亮度法）：

| 品级 | 现值 | 白字对比度 | AA 大字 (3:1) | AA 正文 (4.5:1) |
|------|------|-----------|---------------|------------------|
| A | `#16a34a` | **3.3:1** | 勉强过 | ❌ |
| B | `#65a30d` | **3.1:1** | 勉强过 | ❌ |
| C | `#d97706` | **3.2:1** | 勉强过 | ❌ |
| D | `#dc2626` | 4.8:1 | ✅ | ✅ |

横幅上只有 40px 大字母算"大字"；**"当前品级"10px、置信度 16px、徽章 10–12px 全是正文级，在 A/B/C 底色上全部不达 AA**。产线环境光照复杂、操作员可能斜视/远视，对比度应留足余量。

**方案**：品级 ramp 整体下沉一档深度，同时拉大字重补偿明度损失：

| 品级 | 建议值 | 白字对比度 | 语义 |
|------|--------|-----------|------|
| A | `#15803d` (green-700) | 5.0:1 | 良好 |
| B | `#a16207` (yellow-700) | 4.9:1 | 中等 |
| C | `#c2410c` (orange-700) | 5.3:1 | 较差 |
| D | `#b91c1c` (red-700) | 7.0:1 | 不合格 |

### D2 A/B 色相距不足，"余光可辨"目标无法达成【P0】

规范 §2 把"3 秒/托盘、余光可辨"列为设计原则，但 A `#16a34a`（绿）与 B `#65a30d`（黄绿）色相距仅约 35°，**在视网膜周边视野（视锥细胞稀疏、蓝黄通道占优）几乎不可区分**；且男性红绿色弱（deuteranopia，约 5%）会进一步合并这两色。

**方案**：改用 绿 → 黄 → 橙 → 红 等距工业色阶（即 D1 建议值），A/B 色相距拉到 60°+，与 C/D 形成单调递进的"健康度"序列，符合直觉（绿好红坏）。

### D3 反对"横幅移除一切文字描述"——应补品级描述词【P0】

规范 §4.1 决策："品级语义色不写在横幅文字描述里，只通过色块 + 大写字母承载"。这个决策过度了：字母 A/B/C/D 是**分类学语言**，新操作员无法判断 A 是好是坏。

**方案**（按业务口径修正）：大字母保留（品级为王不变），右侧加竖分隔 + **品级描述词**：

```
A → 良好      B → 中等      C → 较差      D → 不合格
```

要点：
- A/B/C/D **均为正常品级结果**，不附加"放行/复检/剔除"等动作指令——动作不属于识别系统的语义；
- **"需复检"徽章仅由"置信度低于阈值"触发**（现有 `banner_state` 逻辑即如此），与品级本身无关——C/D 品级不自动意味复检；
- 描述词同时出现在横幅、历史列表项与纠错气泡按钮上，三处措辞一致，培训成本趋近于零。

### D3b "拒采"措辞修正：质量不合格图像同样入库【P1】

质量不合格（模糊/过曝/欠曝）的图像**不是拒采丢弃，同样存入数据库**。当前 UI 文案"拒采""未出品级"传达了错误的丢弃语义。

**方案**：横幅与历史项统一改为 `图像质量不合格 · {原因} · 原图已入库`；历史项 chip 用"质量异常"而非"拒采"——同时避免与品级 D「不合格」撞词。筛选下拉"拒采"选项同步改名"质量异常"（过滤值不变）。

### D3c 取景器按正方形画面设计【P1】

相机画面为正方形（2048×2048），取景区域应按**高=宽**设定并让图像铺满整个设定区域，左右由深色画框自然延伸，不再出现非匹配比例造成的缩放留白。当前 `CameraView.set_live` 直接按控件矩形 `KeepAspectRatio` 缩放，宽屏窗口下画面两侧留黑边明显。

### D3d 计量单位统一为"盘"【P2】

顶部统计等所有计数场景用"今日 1,240 盘"（原评审稿误写"托"）；统计 chip 中"通过率"与前后文字留足间隔，避免 12.5px 小字粘连。

### D4 历史列表选中态用橙色，违反自家正交原则【P1】

规范 §6.1 与 `style.qss` 实现：`item:selected { background:#fff7ed; border:1px solid #fdba74 }`——浅橙底 + 橙边框。但橙色在本系统中已被两处占用：品级 C、低置信警告。选中态是**纯导航语义**，用橙色会在列表里制造"一排警告"的错觉。

**方案**：选中态改中性 slate（`#eef2f7` 底 + `#94a3b8` 边框 + 左侧 3px **品级色**条），左条保留品级信息，底/边框只表达"选中"。

### D5 顶部统计栏信息过载，应折叠为单 chip【P1】

56px 顶栏常驻 6 组数字（A/B/C/D/纠错/不合格）+ 磁盘 + 铃铛 + 模式切换 + 运行状态。对操作员而言，每托盘品级分布是**管理数据**，不属于 3 秒决策回路，常驻只会稀释横幅的注意力权重。

**方案**：折叠为单 chip `今日 1,240 盘 · 通过率 96.2% ▾`（"通过率"与前后文字留足间隔），点击展开 popover 显示完整分布（工程师/班组长视角）。顶栏右侧只保留：统计 chip、磁盘、通知铃。

### D6 模式切换改分段控件 + 权限暗示【P1】

`操作员 ▾` 下拉按钮看不出当前状态与切换目标的关系，且单击即切换工程师模式（未配密码时）有误入风险。改分段控件 `[操作员 | 工程师 🔒]`：当前段高亮，工程师段加锁图标暗示门槛；未设密码时点击即切但有一次性确认 toast。

### D7 底栏按钮无主次、开始/停止相邻等大，与"抗误触"目标矛盾【P1】

规范 §2 宣称操作员模式"抗误触"，但底栏四个按钮等大等距排列，`开始运行` 与 `停止运行` 紧邻——这是产线上最昂贵的一对误触。

**方案**：
- `开始运行` 主按钮：放大（min-width 170px、高 44px）、实心绿、运行时置灰禁用；
- `停止运行` 与开始之间加 20px+ 竖分隔线拉开物理距离，红色软底（非实心，避免与品级 D 红混淆层级）；
- `连接相机` 降为 ghost 按钮并旁注连接状态（`相机已连接 · MV-CS200`）；
- 补上按钮状态机（当前实现开始/停止恒可点）：idle 时停止禁用、运行时开始禁用。

### D8 Emoji 图标改 SVG 图标体系【P2】

`💾 🔔 ⚠ ✎` 在 Windows 渲染为彩色 emoji，与浅色现代 SaaS 基调风格跳戏，高 DPI 下发虚，且无法着色匹配语义色。统一改 1.5px 描边线性 SVG（磁盘/铃铛/铅笔/警告三角），通知铃补未读数角标（当前 🔔 是纯装饰，无交互定义——要么接 toast 历史列表，要么移除）。

### D9 字号下限 11px【P2】

历史项时间 9px、参数栏组标题 9px、"已改X"角标 8px——低于桌面 UI 可读下限。产线视距通常 0.8–1.5m，**正文下限 12px、辅助信息下限 10.5–11px**，全部上调。

## 3. 优化后设计 token（v3，替代规范 §4.1 品级色部分）

```
--grade-a: #15803d   /* 白字 5.0:1 */
--grade-b: #a16207   /* 白字 4.9:1，与 A 色相距 60°+ */
--grade-c: #c2410c   /* 白字 5.3:1 */
--grade-d: #b91c1c   /* 白字 7.0:1 */
--sel-bg:  #eef2f7   /* 选中态中性底（原橙底废除） */
--sel-border: #94a3b8
字号：正文 ≥12px，辅助 ≥10.5px，组标题 11px/600/大写间距 1px
品级描述词：A 良好 / B 中等 / C 较差 / D 不合格（正常品级，非动作指令）
复检语义：仅 confidence < threshold 时显示 ⚠ 需复检
质量异常：图像质量不合格 · {模糊/过曝/欠曝} · 原图已入库（chip "质量异常"，不用"拒采"）
计量单位：盘
取景器：正方形画面高=宽，图像铺满设定区域
```

其余（背景/表面/边框/文字 slate 体系、圆角、阴影）沿用原规范 §4，不变。

## 4. 工程师模式界面要点（v3 稿第二屏）

- 左侧参数栏 270px：相机（触发模式/触发防抖/分辨率+应用/曝光）→ 模型（当前模型/置信度阈值）→ 质量检查（模糊/过曝/欠曝阈值，v3 由占位扩为三项数值输入）；**软件间隔行仅"软件连续"触发时显示**（虚框暗示条件性）。
- 操作按钮纵向排列于参数栏底部（连接/开始/停止/拍照），状态机与操作员底栏一致；栏底常驻吞吐统计（平均耗时 · 超时 · 质量异常）。
- 主区与操作员模式完全复用：同款品级横幅（略降高至 84px）+ 正方形取景器 + 历史列表，两模式切换无布局跳动。
- 顶部统计栏与操作员模式逐像素一致（规范原则保留），仅分段控件高亮"工程师"。

## 5. 落地建议（按优先级）

- **P0（视觉正确性）**：D1+D2 品级 ramp 换色（`style.qss` 6 行 + 各组件内 `_GRADE_COLOR` 字典同步）、D3 品级描述词（横幅/历史项/纠错气泡三处）。
- **P1（交互安全与语义）**：D3b 去"拒采"措辞、D3c 正方形铺满、D4 选中态去橙、D5 统计折叠、D6 分段控件、D7 底栏主次 + 状态机（I5）。
- **P2（打磨）**：D3d 单位"盘"、D8 SVG 图标、D9 字号、I1 质量原因翻译统一、I2/I3 进度条与 spinner、I4 toast ×、I6 气泡浅色化、I7 空状态、I8 全屏实现或文案移除、I9/I10 样式架构收敛。

> 建议先在 `style.qss` 落地 P0 换色（半小时工作量、全程序生效），再按 §12.2 的阶段化节奏合入组件级改动。
